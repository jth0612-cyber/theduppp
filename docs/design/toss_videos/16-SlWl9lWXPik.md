- 06:02 주소 입력: 한 화면에 몰아 받지 않고 한 번에 하나씩 묻는다. 쉬운 직업부터 묻고, 이미 저장된 정보는 단계째 건너뛴다.
- 07:27 질문 순서 A/B/C 테스트: 순서, 위치, 문구에 따라 최종 신청률이 크게 달라졌다.

- 08:28 최종 신청 흐름 12개 화면을 가로로 나열: 카드 색상 선택 → 영문 이름 확인(미리 채워 둔 KIM / TOSS) → 약관 동의 → 주민번호 → 직업 → 자택 주소 → 직장 정보 확인 → 카드 받을 곳 → 결제 계좌 은행 → 계좌번호 → 결제 정보 확인 → 비밀번호. 모든 화면이 "~해주세요" 제목 한 줄과 하단 파란 버튼 하나 구조다.
- 08:58, 09:09 사용자 유형별 분기를 다이아몬드 판단 노드와 빨강/초록 화살표로 그린 흐름도를 큰 화면에 띄워 논의.

## 가져올 규칙
- 회원가입이나 수강 신청 폼에서 답이 사실상 정해진 질문은 묻지 말고 기본값으로 처리한다. 바꿀 수 있게만 둔다. (03:27-03:53)
- 질문을 줄이려면 화면만 고치지 말고 운영 정책(필수 항목, 선택지 종류)부터 줄일 수 있는지 먼저 따진다. (03:54-04:05)
- 사용자 상황에 따라 필요 없는 단계는 통째로 건너뛰게 분기한다(예: 이미 학부모 번호가 있으면 연락처 단계 생략). (05:16-05:54, 06:58-07:18)
- 주소, 학교, 학부모 정보처럼 긴 입력은 한 화면에 몰지 말고 한 화면에 한 질문씩 나눈다. (06:25-06:45, 06:40 화면)
- 질문 순서는 답하기 쉬운 것부터 둔다(예: 학년 선택 다음에 학교 검색). (06:48-06:52)
- 이미 저장된 값은 다시 묻지 말고 미리 채운 확인 화면으로 보여 주고, 하단에 "정보 수정"과 "확인" 두 버튼을 둔다. (06:58-07:05, 07:18 화면)
- 선택 목록은 아이콘, 이름, 보조 설명 두 줄로 구성하고 선택된 항목에 오른쪽 체크를 표시한다. (07:18 화면)
- 사진 촬영이나 파일 업로드처럼 환경을 타는 입력에는 항상 "직접 입력하기" 대안 버튼을 둔다. (04:56-05:12, 04:53 화면)
- 촬영 화면 안내는 무엇을 맞출지와 그 뒤에 자동으로 일어날 일을 두 줄로 쓴다. (04:53 화면)
- 모든 단계 화면은 "~해주세요" 제목 한 줄, 입력 한 가지, 하단 주 버튼 하나로 통일한다. (08:28 화면)
- 같은 질문이라도 순서, 위치, 문구를 바꾼 2~3개 안을 만들어 완료율을 비교하고 결정한다. (07:50-08:40)
- 약관 동의처럼 답이 하나뿐인 단계도 쉽다고 가정하지 말고 이탈률을 따로 본다. (08:23-08:26)
- 사용자 유형별 분기는 판단 노드가 있는 흐름도로 먼저 그리고 팀과 함께 모든 경우를 점검한 뒤 만든다. (07:20-07:24, 08:58 화면)
