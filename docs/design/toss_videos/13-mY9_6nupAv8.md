## 다룬 내용
- 디자이너 한 명의 단독 세션(약 8분 40초). 토스 계좌 연결 과정에서 사용자가 넘어야 하는 입력 4가지(계좌번호, 계좌 비밀번호, 은행 아이디, 은행 비밀번호)를 "산"으로 보고 하나씩 없앤 이야기다.
- 02:19 은행 홈페이지 비밀번호: 남은 횟수와 위험도에 따라 세 단계로 다르게 안내했다. 틀린 이유와 남은 횟수를 보여 주고, 방금 입력한 값이 규정에 맞으면 그 값으로 바로 바꾸게 했다.
- 04:31 계좌번호: "계좌번호를 모른다면?" 버튼으로 은행 앱을 열어 주고, 더 나아가 과거 내 이름으로 보낸 송금 기록에서 내 계좌를 추천했다. 추천 순서는 자주, 많이, 최근 순이다.
- 07:03 사용자가 아무것도 모른다고 가정하고 3개월간 36가지를 고쳤다는 정리.

## 가져올 규칙
- 로그인 비밀번호가 틀리면 틀린 이유와 남은 시도 횟수를 에러 문구에 함께 쓴다(예: "비밀번호가 달라요. 4번 더 틀리면 잠겨요"). (02:42)
- 시도가 몇 번 남지 않았으면 다시 입력하라는 안내 대신 비밀번호 재설정을 먼저, 더 강하게 권한다. (02:48, 03:24-03:47)
- 비밀번호 재설정 때 방금 입력한 값이 규칙에 맞으면 새 비밀번호로 그대로 쓰겠냐고 묻고, 다시 입력하게 하지 않는다. (03:08-03:20)
- 마지막 시도에서 막히면 앱에서 도울 수 있는 경우는 재설정으로 바로 잇고, 도울 수 없을 때만 담당 강사나 행정실에 연락하라고 안내한다. (03:57-04:08)
- 학생이 모를 수 있는 값을 묻는 입력칸 아래에는 "~를 모른다면?" 보조 버튼을 둔다(예: "반 코드를 모르나요?"). (05:01, 06:58 화면)
- 사용자가 직접 입력하기 전에 이미 가진 기록으로 후보를 먼저 추천한다(예: 학부모 연락처 입력 때 기존 등록 번호 제안). (05:44-05:56)
- 후보가 여럿이면 하나만 보이지 말고 모두 보여 주되 자주 쓴 것, 많이 쓴 것, 최근 쓴 것 순으로 정렬한다. (06:33-06:47)
- 앞 단계에서 입력한 값은 다음 단계 상단에 작은 글씨로 다시 보여 줘 무엇을 하는 중인지 알게 한다. (06:58 화면)
- 한 화면에는 질문 한 문장과 입력칸 하나만 두고, 칸 위 라벨로 어떤 값인지 정확히 적는다. (02:45 화면)
- 숫자만 받는 칸(인증번호, PIN)은 큰 숫자 키패드를 바로 띄운다. (06:58 화면)
- 기능을 설계할 때 사용자가 그 값을 "아예 모른다"고 가정하고 각 입력 단계마다 모를 때의 길을 만든다. (07:17-07:33)
