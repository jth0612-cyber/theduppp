## 다룬 내용
- 컨퍼런스 사이트에 모인 질문 약 10개에 토스 디자인 리드가 답하는 Q&A(01:00).
- 공통 철학은 Simplicity, 디자이너 59명 구성, MBTI 비율 같은 가벼운 질문(01:05~04:20).
- 사용성과 심미성의 우선순위, 다른 직군 설득법, 제품 원칙 약 10개로 피드백하는 방식(04:20~06:22).
- 프로토타입 테스트(냅킨 테스트), 채용 기준, 실패를 대하는 태도(06:25~09:54).

## 화면에서 본 것
- 모든 장면이 같은 회의실에서 광각 카메라로 찍은 발표자 단독 화면. 제품 화면이나 슬라이드는 없음.
- 003-33: MBTI 답변 때 "INTP 20%, ENFJ 15%" 자막 그래픽이 겹쳐 나옴. 이 외에 화면에만 있는 정보는 없음.
- 자동 생성 자막이라 오인식이 많음("샘플 act"는 Simplicity, "스카치"는 Sketch, "프라이머"는 Framer로 보임).

## 가져올 규칙
- 사용성을 먼저 갖춘 뒤에 꾸민다. 쓰기 불편한데 예쁜 화면은 내보내지 않는다(04:40).
- 팀 안에 10개 안팎의 제품 원칙을 글로 정해 두고, 디자인 리뷰 피드백을 "원칙 몇 번에 맞다/어긋난다"로 주고받는다(06:00).
- 새 화면은 개발 전에 시안을 프로토타입 도구로 이어, 동료에게 "이걸 누르면 뭐가 나올 것 같나"를 물어보는 빠른 테스트를 한다(06:46).
- 기능이 실패하면 원인을 기록하고 같은 실패를 반복하지 않도록 다음 시안에 반영한다(09:45).
