## 가져올 규칙
- 사용자 인터뷰 질문은 "이 기능 쓰시겠어요?"가 아니라 "지난주에 과제를 어떻게 확인하셨나요?"처럼 실제 행동을 묻는다. (13:20)
- 시안 두 개를 같은 사람에게 차례로 보여주고 선호를 묻지 않는다. 뒤에 본 안이 학습 효과로 유리해진다. 각 안이 문제를 풀었는지만 따로 본다. (13:53)
- 처음 쓰는 학생이 설명 없이 끝까지 갈 수 있게 과제 제출 같은 흐름은 한 화면에 몰지 말고 단계별 화면으로 나눈다. (22:19)
- 각 단계 화면 제목은 지금 할 일을 문장으로 쓴다("제출할 파일을 골라주세요"). (26:59)
- 자주 바꾸는 설정(반 추가, 과목 추가)은 관리자에게 문의하지 않아도 되게 목록 화면에서 가장 잘 보이는 곳에 둔다. (23:49)
- 과목이나 반처럼 빨리 구분해야 하는 항목에는 색 라벨을 고를 수 있게 하되, 색만으로 구분하지 않고 이름을 같이 보여준다. (24:36)
- 숫자 입력 칸 옆에는 자주 쓰는 값을 빠른 선택 칩으로 준다(점수 100, 90, 80 등). (26:59)
- 목록에서 여러 개를 고를 때 팝업에서 순서가 바뀐 새 목록을 띄우지 말고, 원래 목록에 체크박스를 켜서 그 자리에서 고른다. (29:58)
- 작업 중 내용을 잠깐 두고 다른 일을 할 수 있게 임시 저장을 둔다(예: 피드백 작성 중 다른 학생 확인). (27:40)
- 개인정보 동의 같은 부담은 첫 화면에 두지 말고, 사용자가 가치를 맛본 직후(성적표 확인 직전 등)에 묻는다. (41:53)
- 진입 직전에 이미 본 정보를 반복하는 인트로 페이지는 없애고 1~2초 안내로 대신한다. 다만 효과는 실험으로 확인한다. (42:10, 42:56)
- 비회원(학부모 등)도 가입 없이 내용 확인까지는 할 수 있게 하고, 가입은 꼭 필요한 순간에 끊김 없이 이어지게 한다. (44:29)
- 공유 링크로 들어온 사람에게는 미리보기 카드의 큰 제목을 그대로 다시 보여주고 버튼은 하나만 둔다. 사람은 큰 제목의 키워드만 보고 누른다. (47:35, 48:43)
- 의견이 갈리면 팀 투표 대신 동료 한두 명에게 프로토타입을 바로 써보게 하는 짧은 테스트로 정한다. (50:39)
- 매일 쓰는 강사용 화면은 정보를 한눈에 많이 보여주는 밀도를 유지한다. 숙련 사용자는 위치를 외워 눈으로 찾는다. (57:32)
- 메모나 피드백 입력창은 새 창으로 띄우지 말고 학생 정보 페이지 위에 떠서 스크롤을 따라오게 하고, 접기와 좌우 이동을 지원한다. (59:48)
- 입력 칸 순서를 화면에서 정보를 확인하는 순서와 같게 맞춘다. (58:17, 59:48)
- 자주 쓰는 동작(입력창 접기 등)에는 단축키를 준다. (60:35)
- 긴 페이지 검색은 브라우저 Ctrl+F 습관을 살려 같은 키로 열리게 하고, 결과는 "어느 섹션의 어떤 항목"인지 묶어 보여주며 엔터로 다음 결과로 간다. (65:57, 66:43)
- 기존 화면을 갈아엎는 개편은 한 번에 내지 않는다. 핵심 화면 두 개 같은 작은 단위부터 배포하고 옛 화면을 한동안 같이 둔다. (71:24, 72:10)
- 큰 변경은 훨씬 미리, 여러 번 공지하고, 사소한 변경은 공지하지 않아 피로를 줄인다. (69:04)
- 변경 공지는 가장 중요한 한두 가지만, 바뀐 위치를 표시한 캡처 한 장과 질문 링크를 붙여 사용자 말로 쓴다. (70:37, 70:45)
- 스크린 리더 사용자는 안내를 끝까지 듣지 않는다. 애니메이션이 많은 화면은 한 페이지에 한 동작만 있는 대체 흐름을 따로 만든다. (83:35, 84:20)
- 접근성 대응은 시각장애 사용자에게 직접 써보게 하며 여러 번 고친다(이 사례는 8번째 테스트에서 통과). (82:50, 85:06)
- 장애나 학습 어려움을 다루는 문구에서 "특별하다" 같은 표현을 쓰지 않는다. 당사자에게 일상인 것을 특별하다고 하면 차별로 읽힌다. (89:41)
- 문구는 교훈조나 강연 말투를 피하고, 쓴 뒤 여러 사람에게 보여주며 특정 집단을 빗대는 단어가 없는지 확인한다. (88:55, 90:27)
