# 토스ㅣSimplicity 21 - 대출, 새로고침
YouTube: jWCuvU5i6H0

## 다룬 내용
- 따로 있던 "조회 제품"과 "카테고리 제품" 두 메뉴를 "대출 받기" 한 화면으로 합친 과정(01:36). 사용자 5%에게만 먼저 실험.
- 위에는 조회, 아래는 카테고리를 두고 UI 11종과 문구를 실험, 카테고리는 스크롤과 탭 둘 다로 이동 가능하게 함(03:20).
- 결과: 두 제품 동시 이용 82% 증가, 조회 제품 180% 성장(04:24).
- 7분 걸리던 심사 로딩: 기다리지 않고 첫 화면으로 돌려보내고, 로딩 문구를 바꾸고, 끝나면 알림. 이후 개발자가 45초로 단축(04:56~07:12).

## 화면에서 본 것
- 004-00: "대출 받기" 화면. 상단에 가로로 넘기는 카테고리 탭(추천, 신용, 대환, 정부지원, 비상금, 자동차)이 있고 현재 탭에 밑줄. 목록이 스크롤되면 "사잇돌" 같은 구역 제목이 나오고 탭이 따라 바뀜.
- 004-00: 목록 한 칸은 기관명·상품명 두 줄, 그 아래 작은 회색 라벨("금리", "최대")과 큰 값("7.18 ~ 7.58%", "1천 5백만원")을 좌우 두 칸으로 배치. 금리는 파란색, 한도는 검정. 오른쪽 끝에 ">" 화살표.
- 006-10: 조회 시작 화면. 큰 글씨 두 줄 "내게 맞는 대출 / 1분 만에 조회해보세요"만 있음.
- 007-03: "07:00"이 줄어드는 타이머 그래픽으로 로딩 시간 단축을 보여줌.

## 가져올 규칙
- 사용자가 차이를 구분 못 하는 메뉴 두 개는 한 화면으로 합치고, 위아래 구역으로 나눠 보여준다(02:01, 03:20).
- 큰 화면 개편은 일부 사용자(예: 한 반, 5%)에게 먼저 열어 지표로 확인한 뒤 전체에 적용한다(03:02).
- 메뉴 이름은 사용자가 하려는 행동 그대로 짧게 짓는다(예: "과제 보기", "출결 확인")(03:13).
- 카테고리 탭은 탭을 눌러도, 목록을 스크롤해도 이동되게 하고, 스크롤 위치에 따라 현재 탭 표시를 바꾼다(03:43, 004-00 화면).
- 목록 한 칸의 수치는 작은 회색 라벨 위, 큰 값 아래로 두고 두 개까지만 나란히 둔다(예: "점수 / 92점", "제출 / 3월 4일")(004-00 화면).
- 구역 간 높이와 간격은 정해진 간격 값으로 맞춰, 위아래 구역이 서로 다른 제품처럼 읽히도록 한다(04:04).
- 30초 넘게 걸리는 작업(성적 일괄 계산, 대량 업로드)은 로딩 화면에 사용자를 붙잡지 말고, 백그라운드로 돌린 뒤 끝나면 알림을 보낸다(05:24~05:58).
- 어쩔 수 없이 보이는 로딩 화면은 문구 하나로 고정하지 말고 진행 단계에 따라 바꿔 보여준다(05:48).
- 완료 알림은 기계적인 문장 대신 한 일을 구체적인 숫자로 말한다(예: "30명 답안을 2분 만에 채점했어요")(06:18).
- 오래 걸리는 처리는 디자인으로 가리기 전에 개발자와 실제로 줄일 수 있는지 먼저 확인한다(06:29~07:12).
