- 이틀 동안 팀원 20명 이상을 직접 만나 사용 방식을 듣고 "신청"과 "완료" 두 단계만 남기기로 함 (02:14)
- 신청 창구를 사내 포털 한 페이지로 모으고, 반복 입력은 템플릿으로, 시스템이 아는 정보는 질문에서 뺌 (03:55)
- 완료 알림을 슬랙으로 보내고 관리자는 버튼 한 번으로 처리, API 연동으로 자동 완료, 직군에 맞춰 필요한 권한을 미리 체크 (04:53)
- 결과: 1년여 동안 요청 3만 건 이상, 프로그램 200개 이상, 관리자 140명 이상, 2,600시간 절약 (06:40)

## 가져올 규칙
- 신청이나 제출 기능은 흐름을 "신청"과 "완료" 두 단계로 줄이고, 중간 상태는 시스템이 기록한다 (02:58)
- 무엇을 어디서 신청하는지 학생이 찾지 않게, 신청 창구는 한 페이지로 모은다 (03:55)
- 로그인 정보로 이미 아는 이름, 반, 학년 같은 값은 폼에서 묻지 않는다 (04:53)
- 사유처럼 매번 비슷하게 쓰는 칸은 자주 쓰는 답을 선택지로 미리 만들어 둔다(예: "업무용" 템플릿) (04:35)
- 학생의 역할이나 과정에 맞는 항목을 미리 체크해 두고, 학생은 확인만 하게 한다 (06:24)
- 승인이 필요 없는 요청은 관리자 손을 거치지 않고 바로 완료 처리한다 (05:53, 003-48 화면)
- 관리자 처리는 알림 안의 버튼 한 번으로 끝나게 하고, 처리 내역은 자동으로 쌓는다 (05:15)
- 완료 알림은 사용자가 평소 쓰는 메신저나 알림 채널로 보낸다 (05:15)
- 완료 화면은 굵은 한 줄 제목, 두 줄 이하 설명, 다음 행동 버튼 하나로 구성한다 (005-03 화면)
- 완료 화면에서 처리 현황을 어디서 볼 수 있는지 알려 주고, 그 위치를 링크로 건다 (005-03 화면)
- 선택지가 몇 개 안 되는 질문은 드롭다운 대신 체크 표시가 있는 카드를 세로로 나열한다 (007-41 화면)
- 기능을 만들기 전에 실제 사용자 여러 명을 짧게라도 직접 만나 어디서 막히는지 듣는다 (02:14)
- 사용자 의견으로 반복 클릭이 업무를 끊는다는 말이 나오면 그 단계를 자동화 후보로 올린다 (05:33)
