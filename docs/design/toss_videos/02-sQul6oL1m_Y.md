## 가져올 규칙
- 메뉴와 묶음은 운영 조직이나 데이터 출처가 아니라 학생이 하려는 행동(제출하기, 확인하기, 알림 받기)으로 나눈다. (06:30, 13:00)
- 메뉴 이름은 "자료실", "내 문서"처럼 뭉뚱그린 명사 대신 "과제 내기", "성적 보기"처럼 동사로 끝나는 행동형으로 짓는다. (03:00, 19:00)
- 이름이 너무 좁아지면 상위 카테고리 이름으로 맥락을 주고 항목은 일반 이름으로 둔다(예: "시험" 아래 "성적표 보기"). (20:00, 020-16)
- 화면 하나에는 주인공 하나만 둔다. 받은 과제나 알림을 보여 주는 화면에 신규 기능 홍보 배너를 계속 덧붙이지 않는다. (04:00, 04:30)
- 화면을 설명하는 안내 페이지가 필요하다고 느껴지면 그 화면 구조부터 다시 본다. 설명 페이지로 때우지 않는다. (05:00)
- 한 번 신청하면 알림만 오는 기능은 메뉴에 고정 진입점을 두지 않고 알림에서 바로 들어오게 한다. (13:30, 14:00)
- 목록을 몇 개만 보여 주고 "모두 보기"를 붙이면 개수 기준이라는 정책이 하나 더 생긴다. 접기 전에 정말 필요한 구조인지 먼저 따진다. (11:00, 011-09)
- 탭을 나누면 두 번째 탭은 잘 안 보인다. 꼭 봐야 하는 내용은 첫 탭이나 스크롤 위쪽에 둔다. (10:00)
- 여러 단계 검토나 입력은 상단 단계 표시(1~5)와 이전/다음 버튼으로 한 방향으로만 진행하게 해서 빠뜨리는 항목이 없게 한다. 교사의 과제 채점, 상담 기록 작성에 쓴다. (27:30, 027-50)
- 단계를 나누면 어느 단계에서 오래 걸리고 어디서 멈추는지 기록이 남도록 로그를 함께 설계한다. (28:00)
- 교사 업무 화면은 "처리 전 / 처리 중 / 완료" 탭에 개수를 붙이고, 학생이 다시 제출하면 "다시 확인 필요" 같은 할 일 카드가 자동으로 생기게 한다. 사람이 상태를 들락날락하며 확인하지 않게 한다. (30:00, 31:30, 031-38)
- 처리할 일 알림은 메신저로 따로 보내기보다 업무 화면 안에 모아 둔다. 두 곳을 오가면 빠지는 일이 생긴다. (31:00)
- 학부모·학생 안내문은 통째 템플릿 대신 항목 조각(서류 미비, 기한 지남, 재제출 요청 등)을 체크하면 문장이 자동으로 채워지게 만든다. 말투도 함께 통일된다. (34:00, 035-36)
- 자유 입력 칸이 있는 안내문 작성 창에는 개인정보를 넣지 말라는 한 줄 경고를 보내기 버튼 가까이에 둔다. (035-36)
- 외부로 나가는 알림은 개인 번호 문자 대신 기관 이름이 보이는 공식 채널로 보내고, 알림 안 버튼 하나로 전문 확인과 답장이 되게 한다. (35:00, 35:30)
- 개편 후에 기존 사용자가 불편하다고 해도 바로 되돌리지 말고 처음 쓰는 사람이 쉽게 쓰는지 따로 확인한다. (36:30)
- 팀마다 들어오는 비슷한 요청은 공통 기능 하나로 만들고 차이는 옵션(대상 반, 키워드, 제외할 보낸 사람)으로 뺀다. (42:30, 43:00)
- 출시 전에 권한, 폴더, 템플릿 같은 부가 기능을 미리 다 만들지 않는다. 쓰는 모습을 보고 붙인다. (48:30, 49:00)
- 목록에 "전체 / 내가 만든 것" 탭, 검색, 행별 켜기·끄기 토글을 두고 남이 만든 것을 복제해 쓸 수 있게 한다. 실제로 쓰이는 예시가 템플릿보다 더 많이 복제됐다. (49:00, 050-33)
- 복제 같은 동작은 목록에만 두지 말고 상세·설정 화면에도 둔다. 상세에서 목록으로 돌아가면 무엇을 하려 했는지 잊는다. (50:30)
- 큰 권한 기능을 만들기 전에 실수의 원인부터 본다. 제목 옆에 "OO님이 만듦"만 보여 줘도 남의 설정을 고치는 실수가 사라졌다. (51:30, 52:00, 050-16)
- 삭제는 메뉴에서 이름 바꾸기·복제와 구분선으로 떼어 둔다. (050-16)
- 설정 화면은 왼쪽에서 고르면 오른쪽 미리보기가 바로 바뀌게 해서, 학생에게 어떻게 보일지 저장 전에 확인하게 한다. (57:30, 057-34)
- 아무도 쓰지 않는 옵션은 데이터로 확인한 뒤 뺀다. 기능 하나마다 문의, 유지, 갱신 비용이 붙는다. (63:30, 64:30)
- 기본값은 전체 평균으로 정하되, 기관이나 반 단위로 바꿀 수 있게 열어 둔다. 전체 90%가 고르는 값도 한 곳에서는 소수일 수 있다. (65:00, 066-14)
- 사용성 문제는 제품을 모르는 동료 3~5명에게만 시켜 봐도 대부분 드러난다. 화면을 보여 주고 "이걸 누르면 뭐가 나올 것 같아요?"를 물어 본다. (67:30, 68:00)
- 기능이 많은 화면은 사용 빈도로 순위를 매겨 1순위만 먼저 보이게 하고 나머지는 뒤로 미루거나 한 단계 안으로 넣는다. (81:30, 88:00)
- 복잡한 입력은 토스 앱처럼 한 화면에 한 가지씩 순서대로 보여 줘서 다음에 할 일이 바로 보이게 한다. (78:00, 078-02)
- 강조색은 화면에서 가장 중요한 한 곳에만 쓰고, 틀(카드, 바탕)은 흰색과 연한 회색으로 둬서 내용이 앞에 서게 한다. (87:00, 87:30)
