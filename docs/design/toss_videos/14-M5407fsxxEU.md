## 가져올 규칙
- 보상이나 포인트(출석, 과제 완료)에는 숨은 조건을 붙이지 않는다. 받는 조건이 있다면 버튼을 누르기 전 한 줄로 모두 보여 준다. (06:45-06:55, 06:49 화면)
- 사용자에게 조건을 확인하는 예/아니요 창을 여러 개 연달아 띄우지 않는다. 확인이 필요하면 한 화면의 체크 목록 하나로 합친다. (06:49 화면)
- "누구나 100%" 같은 과장 문구로 클릭을 유도하지 않는다. 결과와 다른 기대를 만드는 문구는 다크 패턴으로 본다. (01:15 화면, 09:36-09:59)
- 짧은 답을 받는 칸에는 글자 수 카운터(예: 0/3)를 칸 바로 아래 둔다. (04:48 화면)
- 확인 버튼은 키보드 바로 위에 붙이고, 입력 전에는 옅게 비활성으로 둔다. (04:48 화면)
- 선택 화면 제목은 질문 한 문장으로 쓰고 바로 아래 선택지를 카드로 깐다(예: "어느 반 숙제를 볼까요?"). (06:25 화면)
- 학습 퀴즈에서 막히면 정답을 바로 주지 말고 정답을 찾을 수 있는 자료(교재 쪽, 영상 구간)로 가는 힌트를 준다. (03:33-03:53)
- 퀴즈나 과제를 마친 바로 그 화면에 다음 행동(다음 단원, 오답 복습)으로 가는 버튼을 둔다. (04:22-04:29)
- 새 기능 아이디어는 반나절 안에 프로토타입으로 만들어 학생 몇 명에게 직접 써 보게 하고 판단한다. (03:39-03:56)
- 성과가 낮을 때 제한을 늘리는 대신 사용 흐름을 잘게 쪼개 단계별로 실험하고, 실험 화면을 한 캔버스에 모아 관리한다. (07:53-08:30, 08:17 화면)
- 사용자가 받을 대상을 직접 고르게 하고, 고른 뒤에는 따로 기억하거나 신청할 것이 없게 만든다(예: 알림 받을 과목을 고르면 끝). (06:38-06:58)
