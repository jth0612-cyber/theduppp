# 토스 규칙 적용 점검표 (모든 화면, 모든 부품)

근거: `docs/design/toss_reference.md` (글 113편, 영상 28편), 영상별 메모 `docs/design/toss_videos/`, `DESIGN.md` 맨 위 토스 층.
색과 아이콘은 이미 정했다(바탕 #eceef0, 파랑 #2f6fc4, 빨강 #d02028, 토큰은 style.css 끝 토스 층). 이 점검표는 그 밖의 모든 것.

## 화면을 만들거나 고치기 전에 (2026-11-26, 우디디자인랩 '릴스처럼 바꾸는 매뉴얼'에서)
- 세 줄을 먼저 적는다. 무엇(어느 화면), 누가(학생, 조교, 선생님, 학부모 중 누구이고 어떤 상황인지), 할 일(이 화면에서 꼭 끝내야 하는 한 가지).
  예: 회차 화면의 학생 OMR / 현장에서 학생 옆에 선 조교, 휴대폰 / 그 학생이 고른 답과 틀린 문항을 바로 보여 주기.
- 스킬과 도구가 대신 정해 주지 않는 다섯 가지는 사람이 정해 적어 둔다: 쓰는 사람, 그 사람이 꼭 끝내야 할 일, 버튼이 안 눌릴 때 보여 줄 이유, 되돌릴 수 없는 결정 앞의 확인, 우리 서비스의 말투(해요체, 필요한 사실만).
- 흔한 AI 스타일을 피한다: 보라색 그라데이션, 이모지 장식, 가운데 정렬만 있는 화면.
- 색, 글자 크기, 간격, 모서리, 버튼 높이는 정해 둔 값(style.css 끝 토스 층의 토큰)만 쓴다. 화면마다 새 값을 만들지 않는다.

## 화면 하나
- 한 화면에 한 가지 일. 그 화면의 일과 상관없는 덩어리는 다른 화면으로 보내거나 접는다.
- 맨 위: 큰 굵은 제목 한 줄(h1). 부제가 꼭 필요하면 회색 한 줄. 같은 말을 제목, 부제, 탭에서 되풀이하지 않는다.
- 주요 버튼은 화면에 하나(파랑). 나머지는 회색 버튼이나 글자 링크. 휴대폰에서 폼의 주요 버튼은 맨 아래 가로 전체.
- 화면 안 묶음 순서는 학생이 자주 하는 일 순서. 가장 중요한 숫자 하나가 가장 크게.

## 글
- 해요체. "저장했어요", "없어요", "지울까요?". 명사로 끝나는 짧은 라벨은 괜찮다(버튼, 표 머리, 칩).
- 가운뎃점(·) 금지. 나열은 `<span class="sep" aria-hidden="true"></span>`, 낱말 잇기는 쉼표나 "과/와".
- 빈 말, 되풀이, 당연한 설명, 응원, 안심시키는 덧말 금지. 빼도 뜻이 같으면 뺀다.
- 버튼 문구는 누르면 일어날 일("질문 올리기", "답안 보기"). 질문형 버튼 금지.
- 쉬운 말 표: 오류→문제, 최초→처음, 동일→같은, 해당→그, 기재→적기, 조회→보기, 확인 요망 같은 행정 말투 금지.
- 메뉴, 제목은 학생이 하려는 행동이나 평소 쓰는 말. "새로 온 것"처럼 어색한 말은 "알림"처럼 고친다.
- 범례, 산출 방식, 지표 뜻, 올리기 안내 같은 설명은 화면에 늘어놓지 않고 제목 옆 설명 버튼에 넣는다:
  `{% from "_macros.html" import help %}` 후 `<h2>제목{% call help('제목') %}<p>설명</p>{% endcall %}</h2>`.
  꼭 바로 보여야 하는 경고(한 번만 보이는 비밀번호, 되돌릴 수 없는 삭제)는 그대로 둔다.
- 입력 안내는 칸 안(placeholder). 칸 밖에 회색 문장을 따로 두지 않는다.
- 토스 TDS 공개 가이드(앱인토스 UI/UX 가이드의 UX 라이팅)에서 더한 것 (2026-11-26):
  - "되어요, 되었어요"는 "돼요, 됐어요". "연결되어 있어요"는 "연결돼 있어요".
  - 과한 높임을 줄인다. "선생님께"는 "선생님에게", "~하시겠어요?"와 "~하시나요?"는 쓰지 않는다.
  - 확인 창의 왼쪽 버튼은 "닫기". "취소"는 하던 일이 취소된다고 읽힐 수 있다.
  - 할 수 있으면 능동형("저장됐어요"보다 "저장했어요")과 긍정형("안 돼요"보다 "~하면 할 수 있어요"). 정책상 막힌 것은 부정형으로 분명히 쓰고 이유를 붙인다.
  - 들어오자마자, 또는 나가려 할 때 화면을 가리는 창(알림 동의, 광고)을 띄우지 않는다. 버튼만 보고 결과를 알 수 있게 쓴다.
  - 오류가 아닌데 느낌표 아이콘을 쓰거나 기다릴 일이 없는데 기다림 표시를 쓰지 않는다.

## 목록
- 한 행 = 굵은 제목 한 줄 + 회색 보조 한 줄. 누르면 이동하는 행은 행 전체가 링크이고 오른쪽 끝에 `›` 없이도 눌리는 모양(누름 반응).
- 수치는 작은 회색 라벨 위, 굵은 값 아래. 한 행에 두 개까지.
- 휴대폰에서 3열 넘는 표로 학생 목록을 보여 주지 않는다. 학생 화면의 목록형 표(질문 목록, 공지, 과제, 성적 등)는 휴대폰에서 행 목록으로 보인다.
- 표가 맞는 곳(등급표, 선생님 화면 데이터)은 표 규칙: 머리행과 칸 모두 가운데, 열 너비는 내용, 낱말 중간에서 줄바꿈 금지.

## 빈 상태, 오류, 기다림
- 빈 상태: 짧은 한 문장 + 다음 행동 버튼 하나("아직 질문이 없어요" + "질문 올리기").
- 오류: 무엇이 문제인지와 어떻게 하면 되는지. 칸 오류는 그 칸 바로 아래 빨강.
- 기다림: 무엇을 하고 있는지 보여 준다.
- 잠긴 버튼: 왜 안 눌리는지를 버튼이나 바로 옆에 적는다("모두 고르면 확인"). 이유 없이 회색 버튼만 두지 않는다.
- 되돌릴 수 없을 때: 지워지는 것과 남는 것을 확인 창에 적는다. 확인 창의 오른쪽 버튼은 누른 버튼의 말 그대로("그룹 지우기"), "확인"으로 뭉뚱그리지 않는다.
- 처음 볼 때: 처음 온 사람이 무엇을 누르면 되는지 한 가지가 보이게 한다.
- 화면을 고친 뒤 다섯 순간을 각각 눌러 본다: 비어 있을 때, 기다릴 때, 틀렸을 때, 되돌릴 수 없을 때, 처음 볼 때.

## 입력
- 라벨은 칸 위 짧게. 선택지 5개 이하면 칩(라디오)으로, 그보다 많으면 선택 칸.
- 하나만 고르면 바로 넘어가는 칸에는 확인 버튼이 없다(`data-autosubmit`).
- 이미 아는 값은 묻지 않고 미리 채운다. 선택 사항은 미리 체크하지 않는다.
- 되돌리기 어려운 동작은 `data-confirm`(아래에서 올라오는 확인 시트). 삭제는 빨강.

## 모양
- 회색 바탕 위 묶음은 흰 카드(모서리 20, 테두리 없음, 옅은 그림자 `var(--lift)`). 카드 안 작은 묶음은 회색 칸(`var(--raised)`).
- 예전 디자인 흔적 금지: 1px 테두리 상자, 먹색(검정)으로 칠한 선택 표시, 명조 제목, 작은 대문자 머리말(kicker), 장식 구분선, 예전 초록.
  (예외: OMR의 내 답 검은 원, 3D 방과 과학 그림의 장면 색)
- 간격은 4의 배수(8, 12, 16, 20, 24). 섹션 사이 24 안팎.
- 색은 토큰만(`var(--accent)` 등). 직접 쓴 색 코드 금지(다크 모드가 깨진다).
- 누를 수 있는 것은 높이 44px 이상, 누름 반응(scale .97 또는 회색 바탕).

## 접근성
- 버튼은 버튼처럼 보인다. 장식 아이콘은 aria-hidden. 아이콘만 있는 버튼에는 aria-label.
- 큰 글씨에서 잘리지 않게 고정 높이, 고정 너비를 피한다.
