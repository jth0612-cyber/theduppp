# 시놀로지 NAS에 올리기

DSM 7.2 이상, **Container Manager**(도커)를 쓸 수 있는 모델 기준입니다.
구조는 이렇습니다.

```
학생 브라우저 ──HTTPS(443)──▶ 시놀로지 리버스 프록시 ──▶ 컨테이너(127.0.0.1:8050, 이 앱)
                                (인증서·암호화 담당)          └ /docker/student-lms/instance  ← DB·암호화 키·업로드 파일
```

앱은 NAS 안쪽(127.0.0.1)에서만 열리고, 바깥에서는 HTTPS 리버스 프록시를 거쳐야만 들어올 수 있습니다.

---

## 1. NAS 기본 보안 (먼저!)

학생 개인정보가 들어가므로 아래는 꼭 해 주세요.

- **관리자 계정 2단계 인증**: 제어판 → 사용자 및 그룹 → 고급 → 2단계 인증 적용
- 기본 `admin` 계정은 **비활성화**하고, 다른 이름의 관리자 계정을 쓰기
- 제어판 → 보안 → **자동 차단** 켜기 (예: 5분 안에 5번 실패하면 차단)
- 제어판 → 보안 → **방화벽** 켜기. 외부에는 443(HTTPS)만 열기
- **DSM 관리 화면(5000/5001 포트)은 인터넷에 열지 마세요.** 공유기 포트포워딩도 443만
- DSM과 패키지를 최신으로 유지 (제어판 → 업데이트 및 복원)

## 2. 파일 올리기

1. File Station에서 `docker` 공유 폴더 안에 `student-lms` 폴더를 만듭니다.
2. 이 프로젝트 폴더의 내용을 `docker/student-lms`에 그대로 복사합니다.
   - **`.venv` 폴더는 복사하지 않아도 됩니다.** (윈도용이라 NAS에서는 쓰지 않아요)
   - 지금 PC에서 쓰던 데이터를 옮기려면 `instance` 폴더도 같이 복사합니다.
     새로 시작하려면 `instance`는 빼고 복사하세요. 처음 실행할 때 새로 만들어집니다.
   - `instance/demo.sqlite3`, `instance/DEMO_CREDENTIALS.txt`는 체험용이니 지우고 올리세요.

## 3. 컨테이너 실행

1. **Container Manager** → **프로젝트** → **생성**
2. 프로젝트 이름: `student-lms`, 경로: `/docker/student-lms`
3. 원본: **기존 docker-compose.yml 사용**
4. 다음 → 완료. 이미지 빌드에 몇 분 걸립니다.
5. 컨테이너 목록에 `student-lms`가 **실행 중**이면 성공입니다.

## 4. 강사 계정 만들기 (처음 한 번)

Container Manager → **컨테이너** → `student-lms` 선택 → **작업 → 터미널 열기** → **생성 → bash로 실행** 후:

```
python create_teacher.py
```

아이디와 비밀번호(10자 이상)를 입력합니다.

## 5. 주소와 HTTPS 인증서

1. 제어판 → 외부 액세스 → **DDNS** → 추가
   - 서비스 공급자 `Synology`, 호스트 이름 예: `my-lms.synology.me`
   - "Let's Encrypt 인증서 받기"를 체크하면 인증서까지 자동으로 받습니다.
2. 공유기에서 **443 → NAS 443** 포트포워딩 (공유기 관리 화면에서 설정)

## 6. 리버스 프록시

제어판 → 로그인 포털 → 고급 → **리버스 프록시** → 생성

| 항목 | 값 |
|---|---|
| 이름 | student-lms |
| 소스 프로토콜 / 호스트 이름 / 포트 | HTTPS / `my-lms.synology.me` / 443 |
| HSTS 활성화 | 체크 |
| 대상 프로토콜 / 호스트 이름 / 포트 | HTTP / `localhost` / 8050 |

**사용자 지정 머리글** 탭 → 생성 → **WebSocket** 을 누르면 기본 헤더가 들어갑니다. 그리고 아래 두 줄을 직접 추가합니다.

| 머리글 이름 | 값 |
|---|---|
| X-Forwarded-For | `$proxy_add_x_forwarded_for` |
| X-Forwarded-Proto | `$scheme` |

> 이 두 줄이 있어야 로그인 시도 제한과 접근 기록에 학생의 실제 IP가 남고, 로그인 쿠키가 HTTPS 전용으로 동작합니다.

그다음 제어판 → 보안 → 인증서 → 설정에서 `my-lms.synology.me` 서비스에 방금 받은 인증서가 연결돼 있는지 확인합니다.

이제 `https://my-lms.synology.me` 로 접속하면 로그인 화면이 나옵니다.

## 7. 백업 (꼭)

- `docker/student-lms/instance` 폴더 하나에 **모든 데이터**(DB, 업로드 파일, 암호화 키)가 들어 있습니다.
- **Hyper Backup**으로 이 폴더를 매일 백업하세요. 백업 작업 설정에서 **클라이언트 측 암호화**를 켜세요.
- `instance/.env` 안의 `FIELD_ENCRYPTION_KEY`는 **USB 등 NAS 밖에 따로 한 부** 보관하세요.
  이 키가 없으면 백업이 있어도 연락처·메모를 복구할 수 없습니다.

## 8. 업데이트할 때

1. 바뀐 코드 파일만 `docker/student-lms`에 덮어씁니다. (**`instance` 폴더는 건드리지 마세요**)
2. Container Manager → 프로젝트 → `student-lms` → **작업 → 빌드** 후 다시 시작
3. DB 구조 변경은 앱이 시작할 때 자동으로 반영됩니다.

## 자주 생기는 문제

| 증상 | 확인할 것 |
|---|---|
| 로그인하면 "요청이 만료되었습니다" | https 주소로 접속했는지, 리버스 프록시에 `X-Forwarded-Proto` 헤더를 넣었는지 |
| 로그인 후 다시 로그인 화면으로 돌아감 | http로 접속하고 있지 않은지 (보안 쿠키는 https에서만 저장됨) |
| 모든 학생이 동시에 "로그인 시도가 너무 많습니다" | `X-Forwarded-For` 헤더가 빠져서 모두 같은 IP로 보이는 상태 |
| 컨테이너가 바로 꺼짐 | Container Manager → 컨테이너 → 로그에서 오류 확인 |
| 시간이 9시간 다르게 찍힘 | docker-compose.yml의 `TZ: Asia/Seoul` 확인 |
